## 固定条件

同一 GitHub Ubuntu runner、Python 3.12.15、SQLite 3.45.1；两条查询分别为
400/300 次迭代，seed=29、depth 上限20、retrieval_width=24、exploration_width=8。
每个场景重复3次，先后顺序交替；每轮新进程，操作系统文件缓存不清空。
每轮持有独立读事务，主索引与外部缓存始终相同，运行前后文件 SHA256 未变。
计时包含统一方法包装的少量开销；没有进行显著性检验或跨硬件推广。

## 搜索行为与边界

所有场景在3次重复中路径可复现；对应优化前后的最终paths哈希全部相同。
同场景实际加载、词面命中、随机探索与树中选用数量也一致。
本轮证明了固定案例下可复现的效率提升，没有证明一般情况下召回不变。
外部配额补回修复在其他查询可能改变路径，仍须另测。

所有实际树深均为6，上限20不是实际达到20层。两条主库运行分别选用
294/164条知识；混合运行分别选用245/167条，其中外部选用9/5条。
这些是知识选择，不是同样数量的有效推理或新定理，G5C未被证明。
